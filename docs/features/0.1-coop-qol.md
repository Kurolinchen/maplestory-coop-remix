# Co-op / QoL foundation (Milestone 0.1) — and 0.1b safety repairs

Status:
- Milestone 0.1 implemented on branch `feature/0.1-coop-qol`.
- Milestone 0.1b repairs (`feature/0.1b-earlygame-companions`) supersede the
  audit findings below; both branches share the same downstream gameplay work.

## Goal

Make the server alt-friendly and fast to test for 1–10 friends (ROADMAP 0.1,
GAME_DESIGN §Quality of life, §Core pillars 1 "Solo-first co-op"):

- many character slots, bigger inventory/storage defaults, better stack sizes
- solo-capable boss expeditions, configurable expedition minimums
- convenient skill reset for build testing (SP refund), AP reset unchanged (exists upstream)
- travel QoL verified/configured (upstream `travel_rate` pipeline)
- GM command surface + extended smoke test for fast dev loops
- persistent, accurate per-character onboarding hints (Milestone 0.1b)
- balanced solo / 2-player spawn pacing (Milestone 0.1b)

## Design

All numbers live in a new top-level `coop:` block in `config.yaml`
(parsed by `coop/config/CoopConfig.java` via yamlbeans, accessed through
`coop/config/CoopDefaults.java` which is null-safe and clamps to safe ranges):

| Key | Default | Meaning |
|---|---|---|
| `default_character_slots` | 15 | New accounts start with this many character slots |
| `max_character_slots` | 15 | Cap for slot purchases/GM; raising needs playtest of the v83 char-select UI (client renders slots past 15 unverified) |
| `default_inventory_slots` | 32 | New characters start with this many slots in EQUIP/USE/SETUP/ETC (CASH stays 96; hard server cap 96 stays — packet/client limit) |
| `default_storage_slots` | 16 | New account storage starts with this many slots |
| `storage_slot_cap` | 96 | Storage purchase/GM cap (byte-safe; client trunk grid past 48 unverified — playtest before raising config) |
| `travel_rate_default` | 10 | Default world travel-rate override (higher = faster transports). Used when a world's own travel_rate is unset. Read via `CoopDefaults.travelRateDefault()` (null-safe, clamped 1..1000). |
| `buddy_default_capacity` | 50 | New characters' initial buddy-list size; existing accounts keep their stored value. |
| `expedition_min_size` | `{}` (commented example) | Optional per-type override map, e.g. `ZAKUM: 1`; else solo flag decides |

Solo expeditions: `USE_ENABLE_SOLO_EXPEDITIONS` flipped to **true** (owner-approved).
Effective expedition min size = per-type override if present, else 1 when the solo flag
is on, else the upstream `ExpeditionType` minimum. Decision logic in pure function
`coop/expedition/ExpeditionRules.effectiveMinSize(...)`; NPC scripts reading
`exped.getMinSize()` (Adobis 2030013.js, Horntail gatekeeper 2083004.js, etc.) inherit
automatically. Known side effect (approved): the flag also bypasses Zakum prequests
(2020010.js/2020011.js/2020013.js) — intended for solo-first play.

Stack sizes: DB override table `coop_stack_overrides (item_id PK, max_per_slot)` consulted
by `ItemInformationProvider.getSlotMax` before the WZ lookup (override is cached as the base
value; throwing-star/bullet mastery bonus still adds on top). Seed keeps a small set of
potions/eliks (2000000–2000006 → 300 per slot); extending is a pure data change. The
extended ammo/material seed (`coop-1012`) was repaired in `coop-1031` to drop
misclassified IDs and to add the previously missing Bullets (`2330000..2330006`),
White Scroll (`2340000`) and Magic/Summoning Rocks (`4006000`/`4006001`).

Skill reset: `!resetskill` (gm2) now refunds spent SP per skillbook via
`coop/reset/SkillResetService.resetSkills(chr, refundSp=true)` — sums actual learned levels
per skillbook (`GameConstants.getSkillBook`), removes every learned skill (same removal path
as before, incl. the Aran/Legend intro-skill special case) and refunds via `gainSp`.
Free player-facing AP/SP reset without 505-items is deferred (ties into "NX through gameplay").

Travel: upstream pipeline verified end-to-end (config → `World.getTransportationTime` →
ship/train/plane/cabin timers; `!travelrate` runtime knob). No code change; default stays
`travel_rate: 10`. Permanent fast-travel unlocks deferred to 0.4+ (Legacy/travel rewards).

GM surface added: `!charslots <n>` (gm4, sets account character slots, clamped 1..max),
`!storageslots <n>` (gm4, raises account storage toward target, respects `storage_slot_cap`).
`!charinfo` (gm0) reports the current slot/state summary.
`!rate` (gm4) reports/sets world rates including travel rate.

### Milestone 0.1b repairs (audit B1–B12)

The 0.1 implementation shipped with a handful of audit findings (see the
`session-ses_*.md` companion audits). 0.1b fixes them without changing
0.1's design contract:

| Finding | Repair | Where |
|---|---|---|
| B1: hint markers overflowed `characters.dataString VARCHAR(64)` | New `coop_character_hint_seen (character_id, hint_id)` table and `Character.flushMilestoneHintSaves` invoked inside the existing save transaction | `db/extensions/coop-1030`, `coop/onboarding/CharacterHintState`, `Character.java` |
| B2: `coop-1012` seeded wrong item categories (Monster Sack, quest items, mislabeled bullets) | New `coop-1031` deletes the bad rows and adds Bullets/White Scroll/Magic-Summoning Rock verified against `wz/String.wz` | `db/extensions/coop-1031-stack-overrides-correct.xml` |
| B3/B4: Henesys PQ advertised solo entry but required three players; NPC still rejected solo | `minPlayers=1` in the script; NPC dialog aligned; 3+ still recommended for Bunny stages | `scripts/event/HenesysPQ.js`, `scripts/npc/1012112.js` |
| B5: `!charslots` ignored `coop.max_character_slots` and reported success on SQL failure | Clamp via `CoopDefaults.maxCharacterSlots()`, surface SQL failures via boolean return | `CharSlotsCommand.java`, `Client.java` |
| B6: hints gave every class the wrong directions | `job_filter` column on `coop_milestone_hints`; per-class second-job seed rows; Character passes `job.getId()` to `forLevel` | `db/extensions/coop-1033-class-aware-hints.xml`, `MilestoneHints.java` |
| B8: `Storage.saveToDB` swallowed SQLException and committed while storage stayed stale | Save now propagates `SQLException`; outer transaction rolls back | `server/Storage.java`, `Character.saveCharToDB` |
| B9: no UNIQUE on `storages(accountid, world)` allowed race-created duplicates | New `coop-1032` dedupes rows then adds `uq_storages_account_world` | `db/extensions/coop-1032-storage-unique.xml` |
| B11: `Server.initWorld` read the raw `YamlConfig.config.coop.travel_rate_default` (could NPE) | Routed through `CoopDefaults.travelRateDefault()`; default raised to 10 | `coop/config/CoopDefaults.java`, `net/server/Server.java` |
| B12: smoke test accepted `>=6` coop changesets, no specific ID check | Smoke now asserts exact ID presence, inventory/storage defaults, hint table + column, wrong-family rows = 0, storage unique index | `ops/smoke-test.sh` |
| B10: TreeMap loader collapsed duplicate `min_level` rows | Loader buckets via `computeIfAbsent`; tests cover sort/bucket | `MilestoneHints.java`, `coop/onboarding/CharacterHintStateTest` |
| B7: solo spawn floor was 0.95 with a discontinuity at 3 players | Continuous curve: 0.90 (1), 0.95 (2), 1.00 (3), 1.15 (6+). Only relevant when `USE_ENABLE_FULL_RESPAWN` is OFF. | `MapleMap.getCurrentSpawnRate`, `SpawnRateFormulaTest` |

Solo spawn rate: `getCurrentSpawnRate(n)` returns `0.85 + 0.05 * min(n,6)`.
The formula only matters when `USE_ENABLE_FULL_RESPAWN` is OFF. With full respawn
(the coop 0.1 default for solo testing), the formula is bypassed entirely and every
spawn is requested.

### Deferred to later milestones (owner-approved where noted)

  Recipe: per script, verify mechanics tolerate solo, then lower `minPlayers` and re-run
  `ScriptEvaluationTest` + in-game clear.
- Party cap 6 stays (v83 client party UI limit; GAME_DESIGN says relax "where design allows").
- Char-slot cap raise above 15, storage grid above 48: config knobs exist, defaults stay
  conservative until playtest.

## Manual test steps

GM setup: log out, stop only the gameserver, run `ops/set-dev-gm.sh <character-name>`, then
restart with `ops/start.sh` and log in again (full guarded workflow: `docs/TESTING.md`).

1. Fresh DB (`ops/reset-dev-db.sh`, double-confirm) → `ops/start.sh`; register a fresh
   account → char select shows **15 slots**; create characters until full.
2. New character: inventory UI shows **32 slots/tab**; `!setslot 48` still works;
   `!item 2000004 700` (elixir) → stacks merge up to **300 per slot** (SF2 seed).
3. Storage NPC (char level ≥ 15): storage shows **16 slots**; store/take works;
   `!storageslots 24` raises to 24; buying +4 in cash shop respects cap.
4. Zakum (lv 50+): talk Adobis → register + **start solo expedition**; kill arms/body.
   Repeat Horntail via gatekeeper (2083004). No prequest items required.
5. AP reset: use AP-reset item (5050000) → HP↔STR swap works (upstream path, untouched).
   `!resetskill` → SP fully refunded per skillbook, re-assignable; skill list empty.
6. `!charslots 9` → account drops to 9 slots after re-login (never below characters owned).
7. Travel: Orbis–Ludibrium flight departs in ~1/10 vanilla time; `!travelrate 1` → vanilla.
8. Hint ladder: cross level 10/15/30 on a fresh character. Level 10 message references
   each of the five class towns (class-agnostic). Level 30 message names the correct
   instructor for the current job (Perion/Ellinia/Henesys/Kerning/Nautilus).
9. Verify hint deduplication persists across logout/login: cross level 10, log out,
   log back in, cross level 11 → no re-firing of the level 10 hint.
10. Data checks: `SELECT characterslots FROM accounts; SELECT equipslots FROM characters;
    SELECT slots FROM storages; SELECT * FROM DATABASECHANGELOG WHERE ID LIKE 'coop-%';
    SELECT * FROM coop_stack_overrides; SELECT id, min_level, job_filter FROM coop_milestone_hints;
    SELECT * FROM coop_character_hint_seen;`

## Balance assumptions

- Defaults (15/32/16/96) are generous-for-friends picks, not gameplay-tuned; all in config/DB.
- Stack override 300 for potions/eliks: quality-of-life pick; client renders quantities fine
  (short), shop/trade quantity inputs should be playtested.
- Solo spawn floor 0.90 + 0.05×n curve only kicks in when `USE_ENABLE_FULL_RESPAWN` is OFF.
  The coop 0.1 default is full respawn ON, so the curve is a safety net rather than the
  primary mechanic.
- Risks: char-select UI past 15 slots, trunk grid past 48 slots, oversized stacks in shop UI —
  defaults stay below those thresholds until playtest confirms.
