# Deployment

## Local development (primary)

Everything is wrapped by `ops/` scripts (see `AGENTS.md`). Layout:

- `ops/docker-compose.dev.yml` — dev stack (see D1 in `DECISIONS.md`)
  - `db`: mysql:8.4.0, root password from `ops/.env` (never empty), port **127.0.0.1:3307→3306**,
    named volume `maple-dev-db`, healthcheck
  - `maplestory`: built from repo `Dockerfile`, mounts rendered `ops/config/config.dev.yaml`
    (config.yaml with injected `DB_PASS`), `scripts/`, `wz/`; `DB_HOST=db` env override
- `ops/.env` — generated by `ops/start.sh` from `.env.example` with a random password;
  gitignored, chmod 600. Never read it back in chat output.
- `ops/config/` — rendered config (gitignored)
- `ops/backups/` — DB dumps from `ops/backup-dev-db.sh` (gitignored)

Server ports (for the v83 client on this machine): login **8484**, world 1 channels 1-3
**7575-7577**.

### Routine operations

```
ops/build.sh          # compile + tests (≈1 min, Java 21 via SDKMAN)
ops/start.sh          # create .env/config if missing, docker compose up -d
ops/stop.sh           # docker compose down (volume kept)
ops/logs.sh server    # follow server logs (also: db)
ops/status.sh         # containers, volume, backups, git branch
ops/smoke-test.sh     # start → wait "Cosmic is now online" → check port 8484 → stop
ops/test.sh           # unit tests only
```

### Dev DB lifecycle

```
ops/backup-dev-db.sh            # dump to ops/backups/cosmic-dev-<timestamp>.sql
ops/restore-dev-db.sh [file]    # restore latest or given dump (confirmation)
ops/reset-dev-db.sh             # DESTRUCTIVE: recreate DB volume (double confirmation);
                                # Liquibase rebuilds schema + seed data on next boot
```

The dev DB is persistent across restarts (named volume) and resettable at any time.

## Upstream sync

```
/sync-upstream   # or manually:
git fetch upstream
git switch -c chore/sync-upstream-<date> development
git merge upstream/master        # NEVER rebase, NEVER force-push
# resolve conflicts preferring: our custom packages (coop.*), db/extensions, docs;
# upstream wins inside untouched Cosmic files
```

## Future VPS layout (NOT active — templates only)

OpenCode stays on the local PC. The VPS will run game services only (Linux, Git, Docker,
server, DB). No LLM API keys, no OpenCode.

```
/opt/maple-dev    # dev instance:   compose project maple-dev,  volume maple-dev-db,  network maple-dev-net
/opt/maple-prod   # prod instance:  compose project maple-prod, volume maple-prod-db, network maple-prod-net
```

Dev and prod are fully isolated (separate dirs, projects, volumes, networks, config, secrets).

Local template scripts (refuse to run until configured + explicitly approved):

```
ops/bootstrap-vps.sh   # install docker, create dirs/systemd-friendly layout (idempotent)
ops/verify-vps.sh      # health/readiness checks
ops/deploy-dev.sh      # build + deploy DEV only (prod stays human-only, later)
ops/dev-status.sh      # remote dev status
ops/dev-logs.sh        # remote dev logs
```

Rules: dev deployment needs explicit human approval; **production deployment always needs
explicit human approval**; SSH access only through these scripts once configured.
